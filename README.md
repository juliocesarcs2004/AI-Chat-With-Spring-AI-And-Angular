## Overview

This project is a full-stack AI chat application built with Angular on the frontend and Spring Boot + Spring AI on the backend. The solution uses an OpenAI language model to answer user messages and includes a conversation memory feature for each chat.

The structure was designed to show a real integration between:

- a modern frontend in Angular + Angular Material;
- a REST backend in Java with Spring Boot;
- AI access through Spring AI;
- conversation persistence in a PostgreSQL database;
- container support with Docker Compose for the database.

## Project Goal

The main goal is to allow users to chat with a virtual assistant in a simple and responsive interface, with the ability to:

- send messages in an intuitive chat;
- receive answers generated by an AI model;
- keep a history of conversations by chat;
- create automatic descriptions for each conversation;
- use context memory between messages in the same session.

## System Architecture

The system is divided into two main parts:

1. Angular frontend: web interface for talking with the assistant.
2. Spring Boot backend: exposes REST endpoints for communication with the AI model and memory storage.

Main flow:

```text
User (Angular UI)
        |
        v
POST /api/chat-memory/start or /api/chat-memory/{chatId}
        |
        v
Spring Boot API
        |
        +--> Spring AI ChatClient
        |
        +--> MessageWindowChatMemory
        |
        +--> PostgreSQL (conversation history)
        |
        v
Response from the OpenAI model
```

## Features

### 1. Simple chat

The basic chat API receives a message and returns the model response without storing memory context.

Endpoint:

- POST /api/chat

Main implementation:

- `api-ai/src/main/java/com/juliocesarcs2004/api_ai/chat/ChatController.java`

### 2. Chat with conversation memory

This is the most complete flow in the project. It uses `MessageWindowChatMemory` and `JdbcChatMemoryRepository` to keep context for a conversation and manage multiple chats per user.

Endpoints:

- POST /api/chat-memory/start
- POST /api/chat-memory/{chatId}
- GET /api/chat-memory
- GET /api/chat-memory/{chatId}

Main implementations:

- `api-ai/src/main/java/com/juliocesarcs2004/api_ai/memory/MemoryChatController.java`
- `api-ai/src/main/java/com/juliocesarcs2004/api_ai/memory/MemoryChatService.java`
- `api-ai/src/main/java/com/juliocesarcs2004/api_ai/memory/MemoryChatRepository.java`

### 3. Automatic conversation description generation

When a new chat is created, the application sends the first message to an AI client and generates a short summary (up to 30 characters) to represent the conversation.

This logic is in:

- `MemoryChatService.generateDescription()`

### 4. Conversation memory database

The support tables for Spring AI memory are defined in:

- `api-ai/src/main/resources/schema-postgresql.sql`

Main structure:

- `SPRING_AI_CHAT_MEMORY`: stores conversation messages with `conversation_id`, `content`, `type`, and `timestamp`.
- `CHAT_MEMORY`: stores chat metadata like `conversation_id`, `user_id`, and `description`.

## Backend Configuration

### Prerequisites

- Java 25
- Maven 3.8+
- PostgreSQL running locally or via Docker
- OpenAI key in an environment variable

### Environment variables

In `api-ai/src/main/resources/application.properties`, the OpenAI API key is configured like this:

```properties
spring.application.name=api-ai
spring.ai.openai.api-key=${OPENAI_API_KEY}
```

You need to export the variable before running the app:

```bash
export OPENAI_API_KEY=your_openai_key
```

On macOS/Linux, you can also use:

```bash
echo "export OPENAI_API_KEY=your_openai_key" >> ~/.zshrc
source ~/.zshrc
```

### Database

The project is already configured to use PostgreSQL. The `compose.yaml` file creates a PostgreSQL container:

```yaml
services:
  postgres:
    image: "postgres:latest"
    environment:
      - "POSTGRES_DB=mydatabase"
      - "POSTGRES_PASSWORD=secret"
      - "POSTGRES_USER=myuser"
    ports:
      - "5432"
```

Connection settings in `application.properties`:

```properties
spring.datasource.url=jdbc:postgresql://localhost:5432/mydatabase
spring.datasource.username=myuser
spring.datasource.password=secret
spring.datasource.driver-class-name=org.postgresql.Driver
```

### Chat memory database

The application uses the Spring AI JDBC chat memory repository. Tables can be created manually or by SQL script, as shown in:

- `api-ai/src/main/resources/schema-postgresql.sql`

## Frontend Configuration

The Angular app uses a proxy to forward calls to the local backend.

File:

- `angular-ai/proxy.conf.js`

Example:

```javascript
module.exports = {
  "/api": {
    target: "http://localhost:8080",
    secure: false,
    changeOrigin: true,
  },
};
```

This allows the frontend to call URLs such as `/api/chat-memory` without needing to configure CORS manually in Angular.

## How to Run the Project

### 1. Clone the repository

```bash
git clone <repository-url>
cd AI-Chat-With-Spring-AI-And-Angular
```

### 2. Start PostgreSQL

The easiest way is to use Docker Compose inside the backend directory:

```bash
cd api-ai
docker compose up -d
```

This starts the PostgreSQL container on port `5432`.

### 3. Run the backend

```bash
cd api-ai
export OPENAI_API_KEY=your_openai_key
./mvnw spring-boot:run
```

The backend is available at:

- http://localhost:8080

### 4. Run the frontend

In another terminal:

```bash
cd angular-ai
npm install
npm start
```

The frontend is available at:

- http://localhost:4200

## API Endpoints

### Simple chat

#### POST /api/chat

Request body:

```json
{
  "message": "Explain what artificial intelligence is"
}
```

Response:

```json
{
  "message": "Artificial intelligence is..."
}
```

### Chat with memory

#### POST /api/chat-memory/start

Creates a new chat for the default user `julio` and returns the identifier, description, and first response.

Request body:

```json
{
  "content": "I want to know how Java works"
}
```

Expected response:

```json
{
  "chatId": "...",
  "description": "How Java works",
  "response": "..."
}
```

#### POST /api/chat-memory/{chatId}

Sends another message to an existing chat.

Request body:

```json
{
  "content": "Explain Java collections to me"
}
```

#### GET /api/chat-memory

Returns all chats for the current user.

#### GET /api/chat-memory/{chatId}

Returns the messages from a specific chat.

The project also has a `local` flag to trigger a simulated response instead of calling the real API.

## Important Notes

### Fixed user in memory

The application uses a fixed user:

```java
private static final String USER_ID = "julio";
```

This means that, in the current state, all chats are associated with the same user. If you want to create a multi-user system, this should be updated to receive the user identifier from login or token.

### OpenAI model

The application uses the OpenAI client from Spring AI, and the model configuration can be adjusted based on your account and desired cost. The project only configures the `api-key` and does not fix a specific model in the code, leaving that open to the environment and library setup.

### PostgreSQL usage

The project was configured for PostgreSQL, but the file `schema-mysql.sql` also exists in the repository, which means the app can be adapted to MySQL with a different configuration.

## Troubleshooting

### API key error

If the application fails to start or call the AI service, check whether `OPENAI_API_KEY` was configured correctly.

```bash
echo $OPENAI_API_KEY
```

### PostgreSQL connection error

Check whether the database container is running:

```bash
docker compose ps
```

If needed:

```bash
docker compose down
docker compose up -d
```

### Frontend startup error

Check whether Node.js and the packages were installed correctly:

```bash
node --version
npm install
```

### Backend startup error

To verify the Spring Boot build:

```bash
cd api-ai
./mvnw clean install
```

## ⚙️ Advanced Configuration

### Spring AI Configuration

Spring AI is configured with the following available models:

- **OpenAI GPT-4**: recommended default for better quality
- **OpenAI GPT-3.5 Turbo**: faster and more economical alternative

Modify this in `api-ai/src/main/resources/application.properties`:

```properties
spring.ai.openai.chat.options.model=gpt-4
spring.ai.openai.chat.options.temperature=0.7  # 0.0 to 1.0 (creativity)
spring.ai.openai.chat.options.max-tokens=2000
```

### Backend CORS

If you need to configure CORS, add this to `ApiAiApplication.java`:

```java
@Bean
public WebMvcConfigurer corsConfigurer() {
    return new WebMvcConfigurer() {
        @Override
        public void addCorsMappings(CorsRegistry registry) {
            registry.addMapping("/api/**")
                    .allowedOrigins("http://localhost:4200")
                    .allowedMethods("GET", "POST", "PUT", "DELETE")
                    .allowCredentials(true);
        }
    };
}
```
